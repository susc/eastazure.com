## 目录

## 创建博客文章

要撰写新文章，请在 `src/content/posts/` 目录中创建 Markdown 或 MDX 文件。

你可以将文章放入子目录，以便管理内容。子目录名称会成为文章 URL 的一部分。例如，`src/content/posts/2025/example-post.md` 对应的地址是 `/posts/2025/example-post`。

如果子目录只用于整理文件，不希望影响 URL，请在文件夹名称前添加下划线（`_`）。

```bash
# 示例：文章文件路径及其 URL
src/content/posts/very-first-post.md          -> mysite.com/posts/very-first-post
src/content/posts/2025/example-post.md        -> mysite.com/posts/2025/example-post
src/content/posts/_2026/another-post.md       -> mysite.com/posts/another-post
src/content/posts/docs/_legacy/how-to.md      -> mysite.com/posts/docs/how-to
src/content/posts/Example Dir/Dummy Post.md   -> mysite.com/posts/example-dir/dummy-post
```

> [!TIP]
> 名称以 `_` 开头的文件和目录不会参与路由。可将它们用于草稿、共享资源或仅供内部使用的内容。

## Frontmatter

Frontmatter 是存储文章元数据的主要位置，采用 YAML 格式并位于文件顶部。有关 frontmatter 及其用法的更多信息，请阅读 [Astro 文档](https://docs.astro.build/en/guides/markdown-content/)。

下面列出每篇文章可用的 frontmatter 属性：

<ResponsiveTable variant="striped-minimal">

| 属性               | 说明                                                                                           | 备注                                                    |
| ------------------ | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| **_title_**        | 文章标题（h1）。                                                                                | 必填<sup>\*</sup>                                      |
| **_description_**  | 文章描述，用于文章摘要和页面描述。                                                             | 必填<sup>\*</sup>                                      |
| **_pubDatetime_**  | ISO 8601 格式的发布时间。                                                                       | 必填<sup>\*</sup>                                      |
| **_modDatetime_**  | ISO 8601 格式的修改时间，仅在文章修改后添加。                                                   | 可选                                                    |
| **_author_**       | 文章作者。                                                                                     | 默认值为 `site.author`                                  |
| **_featured_**     | 是否在首页精选区域显示此文章。                                                                 | 默认值为 `false`                                        |
| **_draft_**        | 将文章标记为“未发布”。                                                                         | 默认值为 `false`                                        |
| **_tags_**         | 与文章相关的关键词，使用 YAML 数组格式。                                                       | 默认值为 `others`                                       |
| **_ogImage_**      | 文章 OG 图片，用于社交分享和 SEO。可以是远程 URL，或相对于当前目录的图片路径。                  | 默认值为 `site.ogImage` 或自动生成的 OG 图片             |
| **_canonicalURL_** | 如果文章已发布在其他来源，可设置绝对形式的规范 URL。                                           | 默认值为 `Astro.site` + `Astro.url.pathname`            |
| **_hideEditPost_** | 隐藏文章标题下方的编辑按钮，仅对当前文章生效。                                                 | 默认值为 `false`                                        |
| **_timezone_**     | 以 IANA 格式指定当前文章的时区，仅为此文章覆盖全局 `site.timezone` 配置。                       | 默认值为 `site.timezone`                                |

</ResponsiveTable>

> [!TIP]
> 在控制台中运行 `new Date().toISOString()` 即可获得 ISO 8601 格式的时间。

Frontmatter 中只有 `title`、`description` 和 `pubDatetime` 必须填写。

标题和描述（摘要）对搜索引擎优化（SEO）非常重要，因此 AstroPaper 建议为所有博客文章填写这两个字段。

如果文章中省略 `tags`（即没有指定任何标签），系统会使用默认标签 `others`。你可以在 `src/content.config.ts` 中修改默认标签：

```ts file="src/content.config.ts"
// ...
tags: z.array(z.string()).default(["others"]), // 将 others 替换为你想要的值
// ...
```

### Frontmatter 示例

下面是一篇文章的 frontmatter 示例：

```yaml file="src/content/posts/sample-post.md"
---
title: 文章标题
author: 你的名字
pubDatetime: 2022-09-21T05:17:19Z
featured: true
draft: false
tags:
  - some
  - example
  - tags
ogImage: ../../assets/images/example.png # src/assets/images/example.png
# ogImage: "https://example.org/remote-image.png" # 远程 URL
description: 这是示例文章的描述。
canonicalURL: https://example.org/my-article-was-already-posted-here
---
```

### VS Code 代码片段（可选）

AstroPaper 内置工作区代码片段，可加快新文章创建过程：

- **frontmatter**：插入推荐的 frontmatter 区块；
- **template**：插入基本文章模板，其中包含 `## 目录`。

这些代码片段位于 `.vscode/astro-paper.code-snippets`。如果使用 VS Code 或 Cursor，打开工作区后应该会自动提供这些片段。

## 提示块

AstroPaper 从 v6.1 开始支持提示块。它们由 `rehype-callouts`（Obsidian 主题）提供支持，使用简单的引用语法。

下面是最常用的类型：

> [!NOTE]
> 读者应该了解的补充信息。

> [!TIP]
> 实用建议、快捷方式或最佳实践。

> [!WARNING]
> 可能出错或产生意外后果的情况。

> [!DANGER]
> 可能导致失败、数据丢失或错误行为的严重风险。

> [!INFO]
> 中性的信息背景，紧急程度低于普通提示。

> [!SUCCESS]
> 确认某项操作成功或结果正确。

完整支持的类型包括 `NOTE`、`ABSTRACT`、`INFO`、`TODO`、`TIP`、`SUCCESS`、`QUESTION`、`WARNING`、`FAILURE`、`DANGER`、`BUG`、`EXAMPLE` 和 `QUOTE`，每种类型都有自己的图标和颜色。许多类型还支持别名，例如 `TIP` 可使用 `HINT` 和 `IMPORTANT`，`WARNING` 可使用 `CAUTION`。完整参考请查看 [rehype-callouts 文档](https://github.com/lin-stephanie/rehype-callouts)。

### 可折叠提示块

在类型后添加 `-`，可让提示块默认折叠；添加 `+`，则让它默认展开但仍可折叠：

> [!WARNING]- 继续前请先阅读
> 此内容会保持隐藏，直到读者展开。它适合放置可能打断正文流程的较长注意事项。

> [!TIP]+ 专业提示（默认展开）
> 此内容默认打开，但可以折叠。适合首次加载时仍希望读者看到的可选细节。

### 自定义标题

在类型后添加文本，即可用任意标题替换默认类型名称：

> [!NOTE] 你知道吗？
> 类型后的文本会成为提示块标题。如果省略，则自动使用类型名称。

### 语法汇总

```md
> [!NOTE]
> 补充信息。

> [!WARNING]- 默认折叠
> 展开后才显示。

> [!TIP]+ 默认展开，但可以折叠
> 初始状态为打开。

> [!DANGER] 自定义标题
> 替换默认标题。
```

## 添加目录

默认情况下，文章不包含目录（TOC）。如需添加，请在希望显示目录的位置写入 h2 标题 `目录`（Markdown 中使用 `##`）：

```md
---
# frontmatter
---

下面介绍在 AstroPaper 博客主题中创建新文章的一些建议和技巧。

<!-- [!code ++] -->
## 目录

<!-- 文章的其余部分 -->
```

## 标题层级

关于标题需要注意一点：AstroPaper 博客文章会使用 frontmatter 中的 `title` 作为文章主标题。因此，文章中的其余标题应使用 `h2`～`h6`。

这不是强制规则，但从视觉效果、无障碍和 SEO 角度考虑，强烈建议遵循。

## 语法高亮

AstroPaper 默认使用 [Shiki](https://shiki.style/) 进行语法高亮，并通过 [@shikijs/transformers](https://shiki.style/packages/transformers) 增强围栏代码块。如果不想使用这些转换器，可以将其移除：

```bash
pnpm remove @shikijs/transformers
```

```ts file="astro.config.ts"
// ...
// [!code --:5]
import {
  transformerNotationDiff,
  transformerNotationHighlight,
  transformerNotationWordHighlight,
} from "@shikijs/transformers";

export default defineConfig({
  // ...
  markdown: {
    remarkPlugins: [remarkToc, [remarkCollapse, { test: "目录" }]],
    shikiConfig: {
      themes: { light: "min-light", dark: "night-owl" },
      defaultColor: false,
      wrap: false,
      transformers: [
        transformerFileName(),
        // [!code --:3]
        transformerNotationHighlight(),
        transformerNotationWordHighlight(),
        transformerNotationDiff({ matchAlgorithm: "v3" }),
      ],
    },
  },
  // ...
});
```

## 存储博客内容图片

下面介绍两种存储图片并在 Markdown 文件中使用的方法。

> [!IMPORTANT]
> 如果需要为 Markdown 中的优化图片设置样式，请[使用 MDX](https://docs.astro.build/en/guides/images/#images-in-mdx-files)。

### 存放在 `src/assets/` 目录（推荐）

你可以把图片存放在 `src/assets/` 目录。Astro 会通过 [Image Service API](https://docs.astro.build/en/reference/image-service-reference/) 自动优化这些图片。

引用图片时，可以使用相对路径或别名路径（`@/assets/`）。

例如，要显示路径为 `src/assets/images/example.jpg` 的 `example.jpg`：

```md
![图片说明](@/assets/images/example.jpg)

<!-- 或者 -->

![图片说明](../../assets/images/example.jpg)

<!-- 在 Markdown 中使用 img 标签或 Image 组件不会生效 ❌ -->
<img src="@/assets/images/example.jpg" alt="图片说明">
<!-- ^^ 这是错误写法 -->
```

> [!TIP]
> 严格来说，图片可以存放在 `src` 下的任意目录，`src/assets` 只是推荐位置。

### 存放在 `public/` 目录

你也可以把图片存放在 `public/` 目录。请注意，Astro 不会处理其中的图片，因此它们不会得到优化，需要由你自行完成图片优化。

引用这些图片时请使用绝对路径。既可以使用 [Markdown 图片语法](https://www.markdownguide.org/basic-syntax/#images-1)，也可以使用 HTML `img` 标签。

例如，假设 `example.jpg` 位于 `public/assets/images/example.jpg`：

```md
![图片说明](/assets/images/example.jpg)

<!-- 或者 -->

<img src="/assets/images/example.jpg" alt="图片说明">
```

## 补充内容

### 图片压缩

> [!WARNING]
> 将图片加入博客文章前，尤其是 `public/` 目录中的图片，请先进行压缩。未经优化的图片会显著损害页面性能。

推荐的图片压缩网站：

- [TinyPNG](https://tinypng.com/)
- [TinyJPG](https://tinyjpg.com/)

### OG 图片

如果文章没有指定 OG 图片，系统会使用默认图片。虽然并非必填，但建议在 frontmatter 中设置与文章内容相关的 OG 图片。推荐尺寸为 **1200 × 640** 像素。

> [!TIP]
> 从 AstroPaper v1.4.0 开始，未指定 OG 图片时会自动生成。详情请查看[功能公告](https://astro-paper.pages.dev/posts/dynamic-og-image-generation-in-astropaper-blog-posts/)。
